3. REGRESIONES IDENTIFICADAS
A) Importación XLSX:
El parser actual app/assets/l26_excel_import_core.js leía el valor cacheado <v> y relaciones <hyperlink>, pero descartaba el contenido de fórmula <f>. P.C.F.xlsx almacena las URLs Metro como fórmulas Excel HYPERLINK(...), por ejemplo:
  =IFERROR(HYPERLINK("https://metro.sarapiqui.go.cr/processes/15173394","Abrir expediente"),"Abrir expediente")
Por eso el valor visible/ID sobrevivía, pero la URL se perdía.

B) Apertura PWA/Windows:
PATCH_LECTOR_WINDOWS_2026-08-31.diff introdujo un bloqueo específico de Windows Web/PWA que mostraba el mensaje para abrir la aplicación de escritorio, desviándose del contrato 2026-08-29 de conservar el fallback web.
PATCH_METRO_PROTOCOL_HANDOFF_2026-08-31.diff cambió ese bloqueo por un intento obligatorio de l26-reader:// desde PWA. Si el protocolo/EXE no estaba asociado, la apertura seguía sin ser funcional.

5. CORRECCIÓN APLICADA
- app/assets/l26_excel_import_core.js ahora extrae URL http/https directamente de fórmulas HYPERLINK(...) en <f> y la integra al mismo mapa de hyperlinks usado por el importador.
- Se conserva prioridad de un hyperlink OOXML real si existe.
- index.html / Fiscalizacion_BI_V27_FINAL.html restauran el comportamiento histórico:
  * Android con bridge -> lector Android; si falla -> apertura web.
  * Electron con l26Desktop.openSource -> lector interno; si falla -> apertura web.
  * Shell Electron marcado sin bridge -> l26-reader:// como respaldo nativo.
  * PWA/navegador -> apertura web directa; NO depende de l26-reader ni muestra el bloqueo Web/PWA.
- Si no existe enlace específico, la aplicación conserva DEFAULT_CASE_SOURCE_URL = https://metro.sarapiqui.go.cr/.
- sw.js incrementa la clave de caché para que una PWA instalada no retenga la lógica anterior.
